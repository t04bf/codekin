# 默认简历模板迁移（历史记录）

> 本文记录 2026-10-05 的早期 Vue 迁移方案，当前产品已使用独立 React 前端。以下旧数据结构不再作为后端存储协议或种子数据来源；当前协议与初始化方式以 `10. 私有简历接口与JSON协议-2026-10-05.md` 为准。开发阶段已将默认模板与数据结构统一为版本 1，无 v1/v2 并存。

## 已完成

参考本地 Magic Resume 2.0.8，将九套配置和主要版式迁移为 Vue 渲染：classic、modern、left-right、timeline、minimalist、elegant、creative、editorial、swiss，均为 Codekin 模板版本 1、正文协议版本 1。

前端入口 `/resume/templates`，可从顶栏“简历模板”进入。页面使用本地模板清单展示公开示例，不读取个人简历；提供搜索和实际组件预览。缩略图与大图共用渲染器，保留 A4 宽度再按容器缩放。此步不实现创建/编辑/保存接口或 PDF 导出。

## 配置与正文

- `front/codekin_web_client/src/features/resume/data/templates.json`：前后端共同来源，包括固定内置 ID、模板标识、版本、名称、介绍和默认布局。
- `data/blank-content.json`：SQL default_content 的来源。默认姓名、联系方式和经历均为空，不将示例当成用户真实履历。
- `data/preview-content.json`：仅供模板目录预览的虚构履历。
- `types.ts`：实际 schema v1 类型。正文包含 basic、sections；日期为年月字符串，富文本为受限 JSON 节点，文件只保存字符串 fileId。
- `components/ResumeRenderer.vue`：通过 templateKey + templateVersion 精确查找版本；未知版本报错，不静默切换。复用基本信息、模块、字段、富文本组件；各模板有独立布局样式。

原参考项目的 ResumeData（basic、education、experience、customData、globalSettings）不直接作为 Codekin 保存协议。迁移后使用 content/layout 两列协议，排版参数保持参考配置的颜色和像素间距。之前设计草案的 JSON 是讨论示例，具体字段以本次 types.ts 为准。新增自定义模块不在模板预设顺序中时自动追加到主栏，隐藏模块/条目/字段不渲染。自定义字段支持 TEXT、LINK、DATE、DATE_RANGE、RICH_TEXT，模块支持 fieldDefinitions + items.values。

## 编辑器后续接入

向 ResumeRenderer 传入 templateKey、templateVersion、content、layout 和可选 assets。layout 不传则采用该版本默认布局；assets 是由文件接口解析后的 fileId → URL 映射，不写入持久化正文。切换模板时使用新模板默认布局并按业务规则保留用户可迁移设置，正文保持不变。模板 key/version 可根据后端返回的 templateId 和模板目录获得，不能假设后端永远使用内置固定 ID。

图片、证书通过 assets 映射显示；目前默认示例不依赖任何外部图片。富文本使用 Vue 节点渲染，不使用 v-html；仅支持已定义节点/属性和 http、https、mailto、tel 链接，不复制原项目的任意 HTML 输出路径。编辑器及后端仍须实施完整 schema 校验。

## SQL

- 完整初始化：`deploy/deploy.sql`，尾部生成区块包含三张表及九条默认模板记录。
- 已有数据库：`deploy/sql/20261005_resume_templates.sql`，仅包含简历相关建表及种子数据。
- 两种脚本都是创建缺失表、插入不存在的 key/version，不覆盖已发布版本。固定内置 ID 为 910000000000000001—910000000000000009；若已有相同 key/version，会保留已有记录及其 ID。
- cover_path 为 NULL：当前模板目录直接渲染实时缩略图，不伪造封面链接。
- SQL 字符串采用 UTF-8 十六进制字面量，避免单双引号、反斜杠和 SQL_MODE 改变正文。每条 INSERT 上方保留模板标识和中文名称说明。
- `scripts/generate-resume-sql.mjs` 从模板清单、空白正文和已有表结构草案生成两份脚本，`--check` 验证生成内容一致。脚本不连接数据库。
- SQL 未在正在使用的数据库执行。CREATE IF NOT EXISTS 不负责修改已存在且结构不同的表，如未来出现结构差异应另写明确迁移。
