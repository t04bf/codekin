# 1. 用户建模设计

日期：2026-09-29  
阶段：用户资料与登录基础实现

## 1. 设计范围与现状

本阶段解决用户身份、基础资料和登录认证。基础资料包含头像、昵称、个人简介，以及选填的性别、生日、真实姓名。当前支持手机号/邮箱密码登录及验证码登录，记录最近一次成功登录的 IP 和时间；支持手机号和邮箱绑定或换绑。实体、Mapper、建表脚本和基础接口已加入工程。

## 2. 设计依据

本项目需要稳定的用户身份，用于关联学习记录、能力画像和后续求职数据；同时需要可编辑的基础资料。性别、生日和真实姓名由用户选填，默认不作为公开展示资料，也不视为已实名认证。手机号、邮箱和密码散列属于认证信息，不应混入资料表。练习统计、简历和求职目标属于其他业务，不纳入基础资料表。

## 3. 本阶段建议建立的表

建议先建 `user_auth` 和 `user_profile` 两张表。`user_auth.id` 是全平台稳定的用户 ID，同时保存账号状态、登录标识、密码散列和最近登录信息；`user_profile.user_id` 引用该 ID，保存公开展示字段和非公开的个人字段。认证信息与资料分表，避免普通资料查询顺带读取密码散列；读取完整信息时按需要关联两表。

### 3.1 `user_auth`：账号与登录认证

| 字段 | 建议类型 | 约束 | 含义 |
| --- | --- | --- | --- |
| `id` | `BIGINT` | 主键，非空 | 全平台稳定的用户 ID，由 MyBatis-Plus 的 `ASSIGN_ID` 雪花策略生成。 |
| `status` | `TINYINT` | 非空 | 账号状态；首期可定义正常、禁用，不预设复杂状态流转。 |
| `last_login_ip` | `VARCHAR(45)` | 可空 | 最近一次成功登录的客户端 IP，兼容 IPv4/IPv6 文本形式。 |
| `last_login_at` | `DATETIME(3)` | 可空 | 最近一次成功登录时间，首次登录前为空；统一按 UTC 存储。 |
| `phone` | `VARCHAR(32)` | 可空；非空值唯一 | 已绑定的手机号，保存统一格式并包含国家/地区码。 |
| `phone_verified_at` | `DATETIME(3)` | 可空 | 手机号验证通过的时间；未验证号码不能用于登录。 |
| `email` | `VARCHAR(254)` | 可空；非空值唯一 | 已绑定的邮箱，按统一的大小写与空白处理规则存储。 |
| `email_verified_at` | `DATETIME(3)` | 可空 | 邮箱验证通过的时间；未验证邮箱不能用于登录。 |
| `password_hash` | `VARCHAR(255)` | 可空 | 密码散列；仅验证码注册、尚未设置密码的用户可为空。 |
| `password_updated_at` | `DATETIME(3)` | 可空 | 最近设置或修改密码的时间。 |
| `created_at` | `DATETIME(3)` | 非空 | 创建时间。 |
| `updated_at` | `DATETIME(3)` | 非空 | 最后更新时间。 |

`phone` 和 `email` 至少有一个已验证标识；同一用户可同时绑定两者。非空的手机号或邮箱必须有相应验证时间。密码登录可使用任一已验证标识加同一个密码，未设置密码时只允许验证码登录。密码只保存专用密码散列，不保存明文或可逆密文；散列算法及参数在实现认证模块时统一选定。手机号和邮箱分别建立唯一索引；绑定或换绑时先完成验证码验证，写入时以数据库唯一约束处理并发冲突。

仅在认证成功后更新 `last_login_ip` 和 `last_login_at`；失败尝试、令牌刷新不算成功登录。经过网关或反向代理时，只能依据受信任的代理配置获取客户端 IP，不能直接信任请求自带的转发头。该字段只保存最近一次记录，不能代替登录审计流水。

### 3.2 `user_profile`：基础用户资料

| 字段 | 建议类型 | 约束 | 含义与可见性 |
| --- | --- | --- | --- |
| `user_id` | `BIGINT` | 主键，非空；对应 `user_auth.id` | 资料所属用户，保证一人最多一条基础资料。 |
| `nickname` | `VARCHAR(40)` | 非空；不设唯一约束 | 展示昵称，可在注册后生成默认值；不是登录标识。 |
| `avatar_key` | `VARCHAR(512)` | 可空 | 展示头像的对象存储标识；不存图片二进制或临时签名 URL。具体长度随存储方案核定。 |
| `bio` | `VARCHAR(500)` | 可空 | 个人简介，可用于公开展示。 |
| `gender_code` | `VARCHAR(16)` | 可空 | 用户自填性别；枚举编码 `MALE`、`FEMALE`、`OTHER`，未填写用 `NULL`，默认不公开。 |
| `birth_date` | `DATE` | 可空 | 用户自填生日，默认不公开；不另存可随时间变化的年龄。 |
| `real_name` | `VARCHAR(100)` | 可空 | 用户自填真实姓名，默认不公开；不能据此认定已完成实名验证。 |
| `created_at` | `DATETIME(3)` | 非空 | 资料创建时间。 |
| `updated_at` | `DATETIME(3)` | 非空 | 资料最后更新时间。 |

公开资料接口只返回允许展示的字段，不能直接序列化数据库实体。性别、生日和真实姓名仅在用户本人查看或业务明确授权时返回；后续若有公开展示需求，应单独设计可见性规则。

验证码由服务端生成和核验，阿里云只负责发送；不建立永久验证码表，也不在 Redis 存储验证码明文。Redis 保存短时 HMAC 摘要、核验次数与发送频率；核验成功后原子消费摘要。创建账号时，在同一事务中创建 `user_auth` 和默认资料；先取得 `user_auth.id`，再将其写入 `user_profile.user_id`，资料表不得另行生成 ID。读取用户列表时批量获取资料或一次关联查询，不能逐条查询形成 N+1；普通资料接口不读取 `user_auth`。是否启用数据库外键，应在数据库部署与服务边界确定后再定，但应用层必须保证一对一关系。雪花 ID 在前端接口中按字符串传输，避免大整数精度损失；部署多实例时需确认生成器的节点标识与时钟行为。

## 4. 本阶段不建的表与字段

| 内容 | 处理方式 |
| --- | --- |
| 第三方账号 | 当前未要求第三方授权登录；以后如需支持，再独立设计绑定关系。 |
| 学校、专业、毕业年份、目标岗位、求职地点 | 属于求职画像或教育经历；在规划学习目标、简历功能时按业务设计，不提前采集。 |
| 简历、工作经历、项目经历 | 以后由简历业务建模，不能塞入 `user_profile`。 |
| 做题数、正确率、连续学习天数、能力评分 | 来自提交、练习或评估记录；统计口径确定后再考虑聚合表或缓存，不直接作为基础资料字段。 |
| 身份证号码及证件照片 | 当前基础功能不需要，不提前收集。 |

## 5. 后续需确定

1. **尚未实现的认证流程**：密码找回、账号恢复等流程仍需确定。手机号和邮箱验证码登录未找到账号时自动注册；持有有效会话并验证新标识后可以换绑。密码首次设置无需旧密码，已有密码时需验证旧密码。
2. **雪花 ID 部署配置**：明确多实例节点标识与时钟异常的处理方式，避免生成重复 ID。
3. **头像存储方式**：确认对象存储或文件服务后，再定 `avatar_key` 的格式、长度、默认头像与删除策略。
4. **账号注销与数据保留规则**：决定是否需要注销时间、匿名化流程及关联数据清理；不要直接把 `deleted_at` 当作完整方案。
5. **是否需要公开个人主页**：如需可分享的稳定地址，再考虑与可修改昵称分离的公开标识。
6. **登录审计需求**：当前只保存最近一次成功登录；如需查看历史登录或安全告警，再单独设计登录事件记录及保留期限。

以上事项主要影响后续注册、运维和扩展能力；本次基础接口按单实例开发阶段的约束实现。

## 6. 当前实现

- `deploy/deploy.sql` 定义 `user_auth`、`user_profile`。密码登录只接受已有且对应手机号或邮箱已验证的正常账号；手机号验证码登录在未找到账号时自动创建认证记录和默认资料。
- `POST /api/auth/password/login` 返回 JWT；Redis 以令牌 `jti` 保存有效会话。`POST /api/auth/logout` 删除当前会话；本人资料接口 `GET /api/users/me` 同时校验 JWT 与 Redis。
- `GET /api/users/{userId}` 只返回用户 ID、昵称、头像标识和简介。本人资料接口才返回性别、生日、真实姓名、已绑定标识及最近登录信息。
- `POST /api/auth/sms/login/send` 发送登录验证码，`POST /api/auth/sms/login` 核验后登录；`POST /api/users/me/phone/sms/send` 发送新号码验证码，`POST /api/users/me/phone/bind` 完成首次绑定或换绑。短信接口目前只接受中国大陆 11 位手机号，数据库保存为 `+86` 前缀格式；密码登录接受这两种输入格式。
- `POST /api/users/me/email/code/send` 发送新邮箱绑定验证码，`POST /api/users/me/email/bind` 完成首次绑定或换绑；接口参数、额度及错误码见《2. 邮箱绑定与换绑接口-2026-09-30.md》。
- 换绑只要求当前有效会话和新号码验证码，不验证原号码；持有被盗会话的人也可能发起换绑。原号码解绑后，若再用它验证码登录，将被视为未注册号码并创建新账号。上线前宜评估是否增加近期重新认证、换绑通知和会话撤销。
- 所有业务响应使用 `R<T>`，HTTP 状态统一为 200，调用方必须读取 `code` 判定成功与否。异常处理器统一转换业务异常、认证失败、参数错误和系统异常。日志使用 SLF4J，避免输出密码和令牌。
- 号码认证服务需要在运行环境配置访问凭据、控制台系统签名与匹配的模板。当前发送接口按 IP 每分钟最多十次，单个验证码五分钟内最多核验五次，服务端也设置一分钟发送间隔。上线前还需设计密码尝试限流、账号状态变化时的跨服务会话失效、受信代理 IP 配置，以及雪花 ID 多实例部署策略。
