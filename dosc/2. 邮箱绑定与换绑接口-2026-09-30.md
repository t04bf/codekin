# 邮箱绑定与换绑接口

## 1. 规则

- 首次绑定与换绑共用接口；要求当前有效登录会话，并验证新邮箱收到的验证码。
- 用户 ID 从网关验签后的 `UserContextHolder` 获取，请求体不接受用户 ID。
- 沿用手机号换绑规则，不验证旧邮箱、不要求旧密码，不主动撤销现有会话。持有被盗会话的人也可能换绑邮箱；需要加强保护时应增加近期重新认证。
- 邮箱统一小写存储。同一邮箱只能绑定一个账号；当前已绑定邮箱不可重复绑定，其他账号占用的邮箱不可合并或转移。
- 换绑不改变 `user_auth.id`、用户资料或密码。旧邮箱不再关联当前账号，再用旧邮箱验证码登录时会按现有自动注册规则创建新账号。

## 2. 发送新邮箱验证码

`POST /api/users/me/email/code/send`

通过网关调用，携带 `Authorization: Bearer <accessToken>` 和 `Content-Type: application/json`。

```json
{
  "email": "new@example.com"
}
```

发送前检查账号状态、新邮箱是否与当前邮箱一致及是否被占用。发送通过现有网易 SMTP 适配器完成。

## 3. 确认绑定或换绑

`POST /api/users/me/email/bind`

同样通过网关携带登录凭证。

```json
{
  "email": "new@example.com",
  "code": "123456"
}
```

两个接口均返回 `R<Void>`，HTTP 状态遵循项目约定为 200，调用方读取业务 `code` 判断结果。绑定成功后可调用 `GET /api/users/me` 读取新邮箱。

## 4. 验证码与并发约束

- 绑定验证码与邮箱登录验证码隔离，并按当前用户和目标邮箱保存 HMAC 摘要，不保存验证码明文；验证码只能成功消费一次。
- 登录与绑定共享邮箱/IP 每日额度，复用 `VerificationCodeRateLimiter`，限额和有效期读取现有 Nacos `codekin.user.email` 配置，不新增配置项。
- 冷却按用途与邮箱隔离；绑定核验次数按当前用户和邮箱隔离。
- 用 MyBatis-Plus 条件更新同时写入新邮箱、验证时间和更新时间，旧邮箱条件防止并发覆盖，数据库 `uk_user_auth_email` 唯一索引防止并发重复绑定，不新增表或索引。
- 验证码在数据库更新前消费；数据库冲突或更新失败后，需要重新发送验证码重试。

## 5. 主要业务错误码

| code | 含义 |
| --- | --- |
| `USER_ACCOUNT_UNAVAILABLE` | 当前账号不存在或不可用 |
| `USER_EMAIL_UNCHANGED` | 已绑定当前邮箱 |
| `USER_EMAIL_ALREADY_BOUND` | 新邮箱已被其他账号占用 |
| `USER_EMAIL_BIND_NOT_COMPLETED` | 账号状态或邮箱并发变化，未完成更新 |
| `EMAIL_SEND_COOLDOWN` | 仍在发送中或冷却期 |
| `EMAIL_ADDRESS_LIMIT` / `EMAIL_IP_LIMIT` | 邮箱或 IP 日额度耗尽 |
| `EMAIL_CODE_EXPIRED` | 当前用户、用途及邮箱下无有效验证码 |
| `EMAIL_CODE_INVALID` | 验证码不正确或已被消费 |
| `EMAIL_VERIFY_TOO_FREQUENT` | 核验次数超限 |
| `EMAIL_SERVICE_UNAVAILABLE` | 邮件发送或验证码登记失败 |
