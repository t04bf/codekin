# 默认头像与选择弹窗

日期：2026-10-04。

## 存储与配置

采用用户确认的私有签名访问：数据库中的 `user_profile.avatar_key` 存稳定对象路径，展示接口返回短期签名 URL。浏览器不能解析 Docker 内部地址 `seaweedfs`；文件服务使用 `CODEKIN_STORAGE_PUBLIC_ENDPOINT` 签名，本地为 `http://127.0.0.1:8333`。签名后不能替换域名。

仓库副本 `deploy/nacos-config/codekin-user.yml` 的 `codekin.user.avatar.defaults` 已配置 12 个资源，字段为 `name` 和 `object-key`。所有资源位于 `uploads/avatar/default/`，PNG 文件名不能包含子目录、路径穿越或 URL。配置校验拒绝空目录、重复路径及超过 100 项的目录。图片应已存在于文件服务使用的桶内；签名不是存在性检查，不会自动上传或验证预置图片内容，管理员需保证配置与实际对象一致。

## HTTP 接口

两个接口均通过网关访问，要求登录，沿用 `R<T>` 和 HTTP 200 业务状态码约定。

| 接口 | 返回或入参 |
| --- | --- |
| `GET /api/users/avatar/defaults` | `data` 为按配置顺序排列的 `[{name, objectKey, url}]`；`url` 是临时展示链接 |
| `PUT /api/users/me/avatar/default` | `{"objectKey":"uploads/avatar/default/avatar-01-wink.png"}`；成功 `data=null` |

默认选择须命中用户服务当前配置白名单，账号正常且请求身份来自 `UserContextHolder`；不接受客户端指定 userId 或任意图片 URL。服务端只更新本人资料，保存稳定路径，不保存签名链接。不新增数据表。

文件服务新增内部 `IFileApi.getDefaultAvatarUrls(List<String>)`，仍使用契约版本 2.0 和统一 `RpcResult<Map<String,String>>`。其签名范围严格限定于预置目录，不能用于读取任意私有文件。用户上传头像继续使用原 READY 文件查询及归属核验，不因新增预置资源而放宽。默认目录一次 RPC 批量签名，使用 SDK 本地签名运算，不逐条查询数据库或读取存储对象。

首次手机/邮箱验证码注册在原注册事务中随机分配配置中的路径，不调用 RPC；已有用户保持原头像。获取本人或公开资料时按头像路径分别走默认资源签名或上传文件签名。已选默认头像从目录移除后仍可展示，只要对象保留。若签名服务故障，资料查询仍可返回，前端回退吉祥物；默认列表接口则返回可重试业务错误。

## 前端

点击资料页头像打开居中“选择头像”弹窗：桌面每行六个，小屏四个，共十二个圆形头像，选择状态有边框；下方是上传入口与格式、大小说明，底部取消、确认。控件使用 Element Plus，维持现有品牌色。

默认选择点击确认后保存；本地图片选择后仅创建预览，确认时再直传、核验、保存。取消本地选择不创建存储对象。关闭弹窗或切换选择会释放预览 URL。每次打开重新请求默认目录，以更新签名链接。操作成功或失败均用 ElMessage；失败保留当前选择，便于重试。

默认对象没有 `file_object` 临时上传记录，当前按数据库记录清理的任务不会扫描删除该目录。正式上传历史文件仍沿用原有暂不回收规则。

## 生效与验证

将更新的 `codekin-user.yml` 发布到 Nacos 的 `public` 命名空间、`CODEKIN` Group；先重启更新后的文件服务，再重启用户服务。当前导入不启用动态刷新，发布配置后必须重启用户服务。没有开放匿名读、上传 live Nacos 配置、修改数据库或重启现有服务。
