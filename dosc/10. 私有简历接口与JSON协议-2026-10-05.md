# 私有简历接口与 JSON 协议

在 `codekin_user` 实现当前用户的简历列表、详情、新建、保存和删除接口。MySQL 的 `content`、`layout` 使用 JSON 列，HTTP 也传 JSON 对象，不传被二次编码的字符串。前端已接入云端存取，浏览器只保留内存编辑状态与待重试请求，不保存本地草稿。

## 协议来源

- 唯一结构定义：`contracts/resume/resume-document.schema.json`。
- 空白文档：`contracts/resume/blank.json`；含自定义字段、自定义模块和后端经历的样例：`contracts/resume/example.json`。
- React 的 `src/api/resume-document.generated.ts` 由 schema 生成，后端从同一文件加载校验器。`generate:resume-contract` 从实际前端组件配置生成类型、9 套模板默认数据及其 SQL；`check:resume-contract` 检查生成结果未偏离。
- 开发阶段统一使用一套当前协议：`schemaVersion = 1`，9 套默认模板的 `templateVersion = 1`。没有旧格式适配或重复版本种子。早期草案未上线、不构成需要保留的兼容契约。
- 3 个版本含义不同：`schemaVersion` 表示数据结构；`templateVersion` 表示模板版本；`version` 是该简历每次成功保存递增的并发版本。

## HTTP 接口

统一前缀 `/api/users/me/resumes`，所有接口必须登录，经网关身份验签后从 `UserContextHolder` 获取用户 ID。客户端不提供归属用户。沿用已有 `/api/users/**` 网关路由。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/templates` | 已发布且符合当前协议 的模板默认正文及布局 |
| GET | `?page=1&pageSize=20` | 本人未删除简历及预览内容、排版、私有照片链接；每页最多 100 条，返回 `items/page/pageSize/hasMore` |
| GET | `/{resumeId}` | 本人简历详情 |
| POST | 集合路径 | 新建，服务端生成 ID、时间和初始版本 1 |
| PUT | `/{resumeId}` | 整份替换正文及布局，检查并发版本 |
| DELETE | `/{resumeId}?expectedVersion=1` | 本人简历软删除，检查并发版本；已删除记录可安全重试 |

沿用 HTTP 200 和 `R<T>`：`{ "code": "0", "message": "...", "data": {...} }` 表示成功，业务失败必须检查 `code`。ID、模板记录 ID、文件 ID、并发版本都是十进制字符串，避免 JS 整数精度丢失；时间为 UTC ISO 8601。

POST 请求字段：

```json
{
  "title": "Java 后端开发",
  "templateId": "910000000000000001",
  "schemaVersion": 1,
  "content": {},
  "layout": {},
  "mutationId": "a-unique-edit-id",
  "checkpoint": false
}
```

以上 `content/layout` 仅表示字段位置，不能发送空对象；其完整值参考规范样例。新建不能携带 `expectedVersion`。更新在相同结构上增加 `expectedVersion`，例如 `"1"`；成功返回 `version = "2"`，前端下一次保存必须使用返回的新版本。

`templateId` 是数据库模板版本记录 ID；前端编辑模型中的 `templateId = "classic"` 是渲染组件 key，不能直接传给后端。模板接口返回 `id/templateKey/templateVersion`，本地对应清单是 `templates.json`。响应详情同时返回这三个字段。

## 内容与排版

`content` 包含 `basic/education/experience/projects/certificates/customData/skillContent/selfEvaluationContent`。保留原 React 编辑器的业务字段名，包含原有拼写 `employementStatus`，不在传输中悄悄改名。

`layout` 包含：

- `globalSettings`：字体、字号、颜色、间距、单页等设置。
- `menuSections`：模块 ID、标题、图标、顺序、启用状态。
- `basic`：`photoConfig/layout/icons/fieldOrder`。

自定义基础字段保存在 `content.basic.customFields`；自定义模块以稳定 ID 写入 `layout.menuSections`，条目保存在 `content.customData[模块ID]`。模块/条目 ID 必须唯一，自定义模块不能覆盖标准模块。允许改标题、重排、隐藏、增删。正文中的富文本保留受限 HTML，支持原编辑器的列表、强调、对齐、颜色、高亮和安全链接。拒绝脚本、事件属性、图片 HTML、危险链接和非支持 CSS，不静默截断或删除用户内容。

不保存 `githubKey` 等凭证、`activeSection`、`draggingProjectId`，也不允许客户端覆写服务器 ID、归属或时间。整份文档 UTF-8 最大 1 MiB，单段 HTML 最多 32768 字符；条目、模块及字段都有 schema 中的明确上限。

## 文件引用

已直传证件照保存 `content.basic.photoFileId`；同时 `photo` 必须为空。保存前通过 `IFileApi.getReadyFile` 核验本人所有、`RESUME_PHOTO` 用途和 READY 状态。上传 hook 和编辑模型保留确认后的文件 ID；本地预览可以继续显示 Base64，但转换器不会把预览或临时访问链接入库。

默认图片 `/resume-avatar.png`、用户主动填写的 HTTP(S) 图片链接可用 `photo` 表示，此时 `photoFileId = null`。只有 Base64 的证件照缺少远端文件 ID 时明确要求重新上传。

GET 详情通过 `IFileApi.getResumePhotoUrl` 再次核验本人归属、`RESUME_PHOTO` 用途和 READY 状态，返回 `photoUrl` 与 `photoUrlExpiresAt`。GET 签名有效期为 2 小时，仅在响应中提供，数据库仍保存文件 ID。前端在过期前一分钟重新读取详情刷新地址；刷新不会替换未保存内容或清空撤销历史。创建与保存响应不额外签发读取 URL，前端保留上传预览并在打开详情时取得签名。

保留原证书功能的受限 PNG/JPEG/WebP Base64（单项最多 262144 字符）；未新增证书上传用途或跨模块访问文件表。

## 保存、重试与历史

- 保存用 MyBatis-Plus Lambda 条件同时过滤 `id/user_id/deleted_at/version`，原子递增版本。失效版本返回 `RESUME_VERSION_CONFLICT`，不覆盖其他页面修改。
- 每次编辑生成新的 `mutationId`。同一 PUT 重试必须复用原 ID、原 `expectedVersion` 和原载荷；若最近成功保存正是该请求，返回已有结果，不重复增版或写快照。复用 ID 却改变载荷返回 `RESUME_MUTATION_REUSED`。
- 仅识别最近一次成功修改；期间发生其他修改后重试旧请求，仍返回版本冲突。对象键顺序不影响载荷指纹。
- POST 新建不是幂等操作，发生未知结果时不能盲目自动重试创建；先查列表确认结果。
- 创建保留 CREATE 快照；普通自动保存不永久生成历史。`checkpoint = true` 时新增 MANUAL 快照。正文与快照处于同一事务，快照写入失败整次保存回滚。历史读取与恢复接口暂未提供。删除简历设置 `deleted_at` 并递增版本，列表和详情不再返回；历史与照片文件不物理删除，前端暂未提供恢复入口。
- 新建或切换只接受已发布且兼容的模板；既有简历可继续保留 RETIRED 模板。
- 列表返回当前页的 `content/layout`，复用详情响应结构，首次加载即可渲染预览。模板元数据一次批量获取，私有证件照 ID 去重后一次 `getResumePhotoUrls` RPC；文件服务一次 SQL 核验本人归属、用途与 READY 状态，再本地签发两小时链接。查询次数不会随当前页条数增长，不加载历史版本或逐条读取详情。

## 前端接入（2026-10-06）

- 列表按页请求服务端完整预览数据，卡片使用相同的模板渲染器显示已保存内容，不依赖编辑器内存。首次进入或刷新都可预览；复制时单独读取源简历详情。
- 从模板或空白创建成功后使用服务端 ID 打开编辑页；复制创建独立记录。POST 不自动重试，失败时不注册临时记录并刷新列表，避免不确定结果导致自动重复创建。
- 编辑内容立即更新预览，800 毫秒防抖后串行 PUT。待重试请求只保留在内存；网络失败重试原载荷、原 `mutationId` 和原版本，成功后再发送请求期间的新修改。
- 版本冲突暂停自动保存，保留当前内容；用户可先导出 JSON，再明确确认读取最新版本。撤销与重做恢复内容，保留当前服务端版本与待重试请求。
- 对象键顺序不构成编辑变化。照片签名和上传预览、凭证、选中状态、拖拽状态不进入持久化正文。
- 简历路由需要登录；请求前后校验账号，避免切换账号后处理旧响应或复制旧账号内容。页面卸载后忽略旧控制器响应，同一浏览器页面内重新挂载可重试内存中的请求。
- 移除 IndexedDB 持久化、草稿恢复/导入、本地草稿列表及 UUID 编辑路由。新建成功才注册服务端记录，刷新后通过详情接口重新读取；未成功保存的修改不会恢复。账号切换清空内存编辑状态。未保存时保留离页提示与手动 JSON 导出。
- 浏览器验证使用 `npm run dev:fixture` 的独立 MSW 入口，覆盖模板创建、编辑、自定义字段、刷新恢复、证件照上传并重新读取、复制和删除；模拟数据与业务数据库隔离。截图：`dosc/images/react-cloud-resume-20261006.png`。这项验证不等同于真实 Java 服务端到端联调。
- 后端 HTTP 删除参数绑定及缺失/非法版本已验证；独立真实 MySQL 的 11 项测试通过，覆盖归属、软删除、版本冲突、重复删除、私有照片 URL 不入库等。
